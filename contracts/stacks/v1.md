# GitLab local stack foundation v1

Consumer reference: `kunchenguid/gh-axi` at
`2bffd9a5b60ded64d6c9851683b27a480173a7ee`, `src/commands/stack.ts`.
Provider reads reuse the pinned official-glab 1.112.0 typed project and MR
contracts in `internal/delegate/glab/contract.go`. No new provider route or
provider write is introduced. The legacy native `glab-axi/v1` contract is unchanged.

## Implemented workflow

A stack is an explicitly named **linear chain of existing local branches** with
an explicit existing local base. Each parent must be an ancestor of its child;
the unique merge base must equal the selected parent tip. Equal tips are allowed
for empty branches. Duplicate names, cycles, missing branches, unrelated or
diverged parents and ambiguous merge bases cannot be registered or navigated.

- `stack init <branches...> --base BRANCH --allow-local-metadata`: atomically
  adopt a chain of 1..32 existing branches. Never create a branch or switch HEAD.
- `stack link <branches...> --base BRANCH --mr BRANCH=IID ... --allow-local-metadata`:
  bind a chain of 2..32 branches to existing open GitLab MRs, one per branch.
  Initialize an absent record or bind an identical previously unbound chain.
  Each MR targets its predecessor (the first targets the explicit base).
  Existing nonzero MR bindings, chain order and base cannot be replaced.
- `stack view [--mrs] [--limit N]`: observe this local chain, optionally checking
  saved MRs. Does not discover stacks or MRs, fetch, or initialize metadata.
- `stack checkout BRANCH`, `up [N]`, `down [N]`, `top`, `bottom`, `trunk`:
  switch to one existing member, subject to the checkout contract below.
  Up means toward the last branch; down means toward the base; bottom is the
  first branch, not the base. Distance is 1..32, default 1. No boundary wrapping.

Every leaf requires `--stack NAME --hostname HOST -R NAMESPACE/PROJECT`.
The target flags assert the identity of the **current local repository**;
they cannot redirect work elsewhere. Its unique origin URL must match the
explicit host/project. Local-origin comparison is not proof that a server
exists or that an account owns it. Stack names start with a lowercase ASCII
letter or digit and contain only lowercase ASCII letters/digits, hyphens and
underscores, maximum 64 bytes. Branches are exact local names, not revisions,
remote-tracking refs, MR URLs or arbitrary refspecs. Valid trailing Unicode
whitespace is part of the branch identity and is preserved. `--mr BRANCH=IID`
splits at the final `=` so branch names may themselves contain `=`; the IID must
be a canonical positive decimal int64. Symbolic member refs,
shallow/legacy-grafted history and known GitHub authorities are refused.
Git routing/config environment overrides cannot select a different repository.
Git replacement objects and lazy fetching are disabled for these operations.

## Local metadata and concurrency

Authoritative implementation: `internal/localstack`.
One canonical JSON blob is referenced by `refs/glab-axi/stacks/<name>`:

```json
{"version":"glab-axi/stack/v1","host":"gitlab.example","project":"team/repo","base":"main","branches":[{"name":"model","mr":11},{"name":"api","mr":12}]}
```

`mr: 0` denotes unbound. Record size is at most 64 KiB; unknown fields,
noncanonical encoding, duplicate/edited JSON, unsupported versions and different
project identities refuse. The record has no credentials, local paths, branch
snapshots or remote-operation authority. Linked worktrees share the same Git
metadata. Multiple explicitly selected stack names may describe overlapping
branches; there is no ambiguous implicit selection. Only this tool's supported
operations should author the record.

Branch, base and metadata reads use exact named refs, never revision-name
fallback to similarly named tags. A missing exact ref remains missing, even if
such a tag points to the expected object. Executable identity regressions live in
`internal/product/stack_identity_e2e_test.go`.

Publication uses a compare-and-swap on the prior metadata object (or creation
only if absent) plus exact OID verification for every branch and base.
**OID verification, even with `no-deref`, does not prove ref kind.** The supported
Git `update-ref --stdin` transaction is prepared first, with no-deref applied to
every queued ref. While Git holds those exact ref locks, the implementation
verifies each ref's ordinary kind and OID, including the old metadata ref. Only
then does it commit. A symbolic substitution already present at prepare aborts
before publication; a cooperating Git writer trying it after prepare is refused
by Git's own locks. No branch ref is written. Cancellation before commit closes
stdin to abort the explicit transaction. This contract is tested with Git 2.50.1;
a Git lacking the supported transaction protocol refuses instead of falling back.
It does not protect against hostile direct filesystem edits bypassing Git locks.

A short-lived repository-local `glab-axi-stack.lock` directory serializes this
tool's own local actions across linked worktrees. It is not the ref-kind proof
and does not claim to exclude arbitrary Git commands. A retained directory after
a crash refuses new local actions; inspect active processes before manual recovery.
Git's own transaction locks are never removed or repaired by this tool.

Idempotent identical init/link returns `unchanged`. A conflicting record or stale
ref refuses, with no partial graph publication. Writing the blob before a failed
transaction can leave an unreachable object for ordinary Git GC. A lost commit
acknowledgment reports uncertainty and directs the caller to re-read, never
blindly assume failure or overwrite. The tool does not push metadata; an operator's
separate explicit refspec or mirror push is outside this contract.

## GitLab MR observations

`link` makes two bounded passes over project and exact MR identities. Each pass
checks canonical host/project URL and positive project ID; positive MR ID and
exact IID/URL; same source and target project IDs; exact source/target branch
names; and exact source head equal to the inspected local tip. Both `link` and
`view --mrs` require bound MRs to remain open and match these identities; a closed
or merged MR refuses live observation pending explicit follow-on reconciliation.
Two-pass drift or any failed read means no metadata publication. `view --mrs`
reports an unbound node as incomplete, not as an absent remote MR.

Target-branch relationships are genuine GitLab stacked-MR dependencies, **not a
provider-enforced merge-order constraint**. No merge readiness, approvals, CI,
remote target-tip equality, atomic remote snapshot, or future freshness is
claimed. Remote state can change after observation. No title searches, inferred
MR creation, replay guesses, retargeting, comments or authentication fallback.
Official and native accounts are not assumed identical; this feature uses only
the pinned official-glab read identity.

## Checkout authority and preservation

Each navigation call requires `--allow-checkout`, `--expected-current BRANCH`,
`--expected-head SHA` and `--expected-target SHA`. Both SHAs are full lowercase
object IDs. The destination must belong to the selected chain, including its
base. Current HEAD must be attached to a member or the base. Dirty, staged,
untracked **and ignored** files, hidden index entries, submodules, sparse/partial
checkout, custom filters, active Git operations or known locks refuse. The tool
never stashes, cleans, resets, forces, creates branches, stages or commits.
Checkout hooks and recursive submodule actions are disabled. Git's ordinary
other-worktree branch protection is retained.

The final operation is non-forced `git switch --no-guess --no-overwrite-ignore`.
Expectations and local graph are rechecked immediately before it; current branch,
all branch tips, metadata and local cleanliness are checked afterward. All
unlanded commits remain referenced by their original branches. Git does not offer
an atomic worktree switch together with arbitrary external commands: other Git
operations can race between those checks. A failed/cancelled attempt or uncertain
postcondition reports uncertainty; no destructive rollback or implicit retry is
performed. The stricter prepared-ref guarantee above applies to metadata
publication, not to worktree-wide transactional checkout.

## Bounds and output

Generated closed data schema: `schema/ux-v1/stack.schema.json`. Output uses the
existing `glab-axi/ux-v1` envelope and typed errors, canonical `gl-axi` and alias
`glab-axi`. Local-only output identifies `backend: local`; requested MR reads use
`backend: official-glab` and the observed upstream version.

At most 32 branches, 64 KiB per Git stdout/metadata, 1000 Git invocations, 3 seconds
per ordinary Git command, and 30 seconds per whole operation/transaction. GitLab
reads retain the existing 2 MiB page and cumulative 8 MiB limits; link performs
at most 66 project/MR reads. A view limit clips only displayed branch nodes and
marks incomplete/truncated output; the record itself is never truncated into a
new authority. A missing/diverged local branch is reported in local view with
`complete: false`; requested MR reads or local actions refuse stale graphs.
`complete` applies only to the selected local graph and requested observations,
never all project MRs or stacks. Raw Git diagnostics/configuration are not emitted.

## Explicit remaining parity

Reference leaves `view/init/link/checkout/up/down/top/bottom/trunk` have the
bounded foundation above, not full argument equivalence. Existing-branch adoption
is implemented, not reference-style implicit branch creation; checkout of remote
stacks/MR URLs is not implemented. `add`, `push`, `submit`, `sync`, `rebase`,
`unstack` and `merge` remain real follow-on increments, not aliases or stubs.
Future publication must reuse typed MR operations with partial receipts; future
merge must preserve the existing exact-head guarded merge contract. Reference
implicit `--auto`/`--yes` is never authority here. No full stack parity claim.
